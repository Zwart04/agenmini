# Proyek bertahap dan tim dinamis (0.3.5)

Chat dan Telegram utama memakai Orchestrator. Tugas biasa dikerjakan spesialis lalu diperiksa Reviewer. Orchestrator bisa membuat spesialis domain yang belum tersedia: `create_specialist` mencatat bot sebenarnya, mewariskan hanya alat yang dimiliki pembuat, tidak memberi kredensial baru, dan mengembalikan ID untuk `delegate_task`. Bot baru memakai provider yang sama; semua bot lokal tetap berbagi satu proses model. Maksimal 40 bot, empat penugasan per giliran, empat spesialis baru per rencana. Kelola bot melalui Workspace → Tim bot.

Untuk repositori besar, gunakan Workspace → Proyek berkelanjutan. Isi URL repo GitHub publik dan tujuan/kriteria penerimaan yang spesifik. Agen clone ke folder baru; membaca tree, README, AGENTS dan manifest; menyimpan rencana tahap di SQLite; mengerjakan satu tahap setiap kali; mencatat alat, hasil, exit code dan pemeriksaan. Jeda berlaku setelah tahap aktif. Galat tidak memajukan checkpoint. Proyek selesai tahap masuk **Siap ditinjau**, bukan otomatis dianggap aplikasi produksi. Source ZIP tersedia setelah pemeriksaan akhir. Dependensi, build, integrasi, migration dan deploy perlu bukti nyata masing-masing.

Contoh tujuan: “Di repo ini, perbaiki pagination daftar tugas, tambahkan uji reproduksi, jalankan build yang didokumentasikan, lalu review diff. Pertahankan arsitektur dan data.” Tujuan “buat seluruh Paperclip/Postiz/Gods Eye” perlu rincian fitur dan tahap; model kecil CPU tidak dijanjikan mampu menuntaskan semua aplikasi tersebut. Banyak proyek membutuhkan layanan eksternal dan RAM build lebih besar. Alat berjalan sebagai user kerja; heap Node 192 MB dan perintah maksimal 300 detik. Build proyek diserialkan. Tidak ada akun GitHub/email/sosmed/trading yang dianggap tersambung hanya karena alat muncul.

Koneksi → Smart Router memilih dari endpoint yang tersedia. Prioritas coding API, tugas ringan lokal bila siap. Retry serial antarbackend, berhenti bila streaming telah dimulai. Nama model menjadi heuristik; keberhasilan uji dan model yang benar-benar melayani dicatat. Tombol **Uji koneksi** menguji jawaban aktual; respons HTTP saja belum membuktikan model mengikuti instruksi. Model per Chat/bot dan `/model` tetap dapat dipilih. Gateway 9router dan FreeLLMAPI opsional pada setup; tanpa gateway dapat memakai lokal/API langsung. Fork 9router Go belum dipakai karena adapter model tidak kompatibel pada uji nyata.

Landing page API mendapat anggaran kode lebih besar, pemeriksaan struktur/tautan dan satu percobaan perbaikan. Jika dokumen tetap tidak memenuhi interaksi dasar, copy model dipasang pada fondasi frontend interaktif teruji, dengan batas backend yang jelas. Lokal memakai copy terstruktur pada fondasi tersebut untuk menghemat token/RAM. Berkas diberi nama produk `.html` dan header unduhan yang eksplisit. Game/aplikasi kecil dapat menghasilkan beberapa modul dan ZIP; pemeriksaan sintaks tidak menggantikan uji browser.

`edit_project_file` menulis modul panjang sebagai kode mentah agar tidak terpotong di JSON tool call. Batas source saat mengedit: 24 KB melalui API, 6 KB melalui lokal; source lebih besar memerlukan patch bagian relevan. `preview_project` membuka frontend pada server sementara yang hanya melayani folder halaman, memakai browser terpasang, mencatat exception JS, lalu menutup proses/server. Lightpanda memeriksa DOM/JS; rendering WebGL dan ukuran visual membutuhkan Chromium opsional. Galat, tanpa perubahan source, atau tes wajib tanpa exit code 0 menahan checkpoint. Rencana gagal dapat disusun ulang dari kode yang sudah ada.
